# Эталонная конфигурация «Специалиста»

[English version](reference-machine.en.md)

## Назначение и статус

Документ определяет первую эталонную конфигурацию для Этапа 1: журнальный «Специалист» с Monitor 2. Она выбрана как узкая проверяемая модель, а не как объединение возможностей всех клонов. Monitor 2 выбран по описанию Алексея Морозова как наиболее совместимый с существующими программами вариант.

Степень подтверждения различается:

- **Журнальная схема** — CPU, RAM, видеопамять, разрешение и программная клавиатура подтверждены сканом «Моделиста-конструктора» 1987-02.
- **Monitor 2** — состав и адреса ROM подтверждены отдельной картой памяти Алексея Морозова.
- **Регистры и биты** — уточнены по Emu80 как реализационный контракт, который ещё предстоит проверять тестами.
- **Не утверждается**, что все электрические особенности и варианты «Специалиста» уже доказаны.

## Базовые параметры

| Параметр | Эталонное значение |
| --- | --- |
| Модель | Журнальный «Специалист» с Monitor 2 |
| CPU | КР580ВМ80А / Intel 8080, 2 МГц |
| RAM | 48 КиБ: 36 КиБ `0000–8FFF` и 12 КиБ видеопамяти `9000–BFFF` |
| ROM | 6 КиБ `C000–D7FF`: загрузчик, Monitor 2, знакогенератор |
| Экран | Монохромный, 384 × 256 пикселей |
| Системный интерфейс | КР580ВВ55А, `F800–FFFF` |
| Клавиатура | Матрица 12 × 6 + отдельный Shift |
| Звук и лента | Отложены до Этапа 2, кроме необходимых линий системного порта |

Вариант RAM 32 КиБ, MX, Monitor 1, цветные доработки, SD, таймер ВИ53 и дополнительные контроллеры в эту конфигурацию не входят.

## Карта памяти

| Диапазон | Назначение | Источник и примечание |
| --- | --- | --- |
| `0000–3FFF` | 16 КиБ RAM пользователя | Журнальная схема |
| `4000–7FFF` | 16 КиБ RAM, обозначенные как резервные | Журнальная схема; это не отдельное устройство и не запрет на использование программами |
| `8000–8FFF` | 4 КиБ RAM пользователя | Журнальная схема; Monitor 2 также использует часть верхней RAM для системных целей |
| `9000–BFFF` | 12 КиБ видеопамяти | Журнальная схема и описание видео |
| `C000–C7FF` | 2 КиБ ROM загрузчика | Карта Monitor 2 |
| `C800–CFFF` | 2 КиБ ROM Monitor 2 | Карта Monitor 2 |
| `D000–D7FF` | 2 КиБ ROM знакогенератора | Карта Monitor 2 |
| `D800–EFFF` | Не определено для эталона | Не использовать без отдельной конфигурации |
| `F000–F7FF` | Необязательный порт принтера | Не входит в базовую конфигурацию |
| `F800–FFFF` | Клавиатура и системный порт КР580ВВ55А | Карта Monitor 2 |

Зарезервированная RAM остаётся RAM: конфигурация не должна возвращать для неё специальное значение или запрещать запись. Отдельные условные обозначения областей не меняют физическую карту адресов.

## Системный порт и регистры

Порт КР580ВВ55А отображён на память, а не на 8-битное пространство инструкций `IN`/`OUT`.

| Адрес | Назначение |
| --- | --- |
| `F800` | Порт A: строки 0–7 клавиатурной матрицы |
| `F801` | Порт B: биты 2–7 — столбцы матрицы; бит 1 — Shift; бит 0 — вход магнитофона |
| `F802` | Порт C: биты 0–3 — строки 8–11; бит 5 — звуковой выход; бит 7 — выход на магнитофон |
| `F803` | Управляющий регистр КР580ВВ55А |

Emu80 повторяет эти четыре регистра каждые 4 байта по всей области `F800–FFFF`. Это реализационное правило принимается для проверки, но журнальная схема его отдельно не подтверждает.

Нажатие клавиши и отпускание представляются активным нулём. Направление портов задаётся управляющим регистром. Матрица сканируется в два прохода: сначала строки, затем столбцы; не нажатая линия читается как `1`.

Цветовые биты порта C относятся к доработкам и не используются в монохромном эталоне.

## Контракт клавиатуры

Состояние хранится как 12 строк по 6 бит плюс Shift. Внешнее событие не зависит от операционной системы:

```text
KeyEvent {
  key: идентификатор клавиши или Shift,
  pressed: true | false,
  cycle?: номер такта эмулятора
}
```

Правила:

- последовательность событий детерминирована; `cycle` задаётся только вызывающей стороной, ядро не читает системные часы;
- нажатие устанавливает бит клавиши, отпускание очищает его;
- Shift хранится отдельно и инвертируется при чтении порта B как активный ноль;
- одинаковые входные события при одинаковом начальном состоянии дают одинаковые значения портов;
- одновременные нажатия сохраняются в состоянии матрицы, но ограничения двухпроходного сканирования не скрываются.

Матрица `original` из Emu80 используется для соответствия логических клавиш ячейкам. Раскладки MX, Лик, Eureka и SP-580 не подменяют её автоматически.

## ROM и режим без ROM

Для `specialist-monitor2` ROM-файл имеет размер ровно `0x1800` байт (6 КиБ), загружается с `C000`, стартовый адрес — `C000`:

1. `C000–C7FF` — загрузчик 2;
2. `C800–CFFF` — Monitor 2;
3. `D000–D7FF` — знакогенератор 2.

Monitor 2 и знакогенератор в некоторых машинах необязательны, но эталон включает их для предсказуемой совместимости. Другой размер ROM не принимается молча: нужна отдельная конфигурация загрузчика, Monitor 1 или расширенного ROM.

Отсутствие обязательного ROM должно останавливать запуск с понятной ошибкой до выполнения инструкций. Переключаться на другую модель неявно нельзя.

`demo` — отдельный явный режим без ROM с собственной программой и адресом входа `0000`. Он не утверждает совместимость с Monitor ROM и не имитирует загрузку реального «Специалиста».

ROM-образы не добавляются в репозиторий до подтверждения права на распространение.

## Что не входит и остаётся открытым

- точные видео- и аудиотайминги, лента и снимки состояния — Этап 2;
- дополнительные контроллеры, SD, таймер ВИ53, второй порт принтера и цвет — отдельные конфигурации;
- поведение чтения нераспределённых адресов и open bus — пока не специфицировано;
- электрические эффекты ghosting при нескольких клавишах — моделируются только после отдельной проверки;
- права на ROM и происхождение каждого конкретного образа требуют отдельного подтверждения.

## Проверка эталона

После реализации памяти и портов нужно проверить:

1. чтение и запись всех RAM-областей, включая резервную;
2. запрет записи ROM без специального режима;
3. адрес и порядок пикселей: байт `col * 256 + row`, старший бит слева, `1` — светлая точка;
4. повтор регистров каждые 4 байта и независимость `F803` от данных;
5. нажатие, отпускание, Shift и одновременные клавиши на обоих направлениях матрицы;
6. идентичность состояния и framebuffer в CLI и WASM для одной тестовой программы;
7. ошибку отсутствия ROM до первой инструкции и отсутствие неявной смены модели.

# 0007. Web E2E в настоящем браузере

[English version](0007-web-e2e-in-a-real-browser.md)

Статус: принято (2026-11-03)

## Контекст

Unit-тесты и тесты WASM-границы не проверяют весь UI, загрузку модулей браузером, Canvas и выбор файла. Наличие браузера различается на машине разработчика, в CI и необязательном контейнере.

## Решение

Сценарий E2E остаётся в `tests/e2e` на Vitest и `playwright-core`. Он собирает web-приложение, отдаёт production-результат, использует установленный Chrome/Chromium и проверяет шаг, запуск до HLT и загрузку BIN через настоящий UI без JavaScript-ошибок.

`CHROME_PATH` переопределяет поиск браузера; поддерживаются типичные пути Linux, macOS и Windows. Без браузера набор локально пропускается с предупреждением. `E2E_REQUIRE_BROWSER=1` превращает отсутствие в ошибку и всегда задаётся в CI. Тест не скачивает браузер.

## Альтернативы

- **Только UI unit-тесты.** Быстрее, но не покрывают настоящую цепочку WASM/Vite/браузер.
- **Скачиваемый закреплённый Playwright browser.** Воспроизводимее, но добавляет большой артефакт и шаг установки.
- **Всегда падать без браузера.** Правильно для CI, но излишне ограничивает локальную работу только с ядром.

## Последствия

- (+) Полный пользовательский сценарий проверяется в браузере того же типа, что используется при разработке.
- (+) Необязательное локальное и обязательное CI-поведение заданы явно.
- (−) Firefox и Safari не охвачены.
- (−) Обновления браузера раннера могут выявлять ошибки независимо от изменений приложения.
